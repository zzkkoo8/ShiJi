# MVP_ROADMAP

## 1. MVP 目标

MVP 只回答一个问题：

> **“玩家直接操作将领，同时用少量军令影响 AI 军团”是否真的好玩，并且能在 PC 和手机上自然操作？**

在这个问题被验证前，不扩大历史内容、城市规模和系统数量。

## 2. MVP 场景

制作一张**非正式历史关卡的测试战场**，避免原型阶段就被史料和大规模美术制作拖慢。

场景包含：

- 一块可读性清晰的野外战场
- 少量高低差和道路
- 一个友方营地
- 一个敌方据点
- 简单补给点

视觉先使用灰盒和低成本占位资源。

## 3. 必须完成的玩法

### 玩家英雄

- 第三人称/斜俯视可玩摄像机方案二选一，通过试玩决定最终视角
- 移动
- 普通攻击
- 防御或闪避
- 3 个技能
- 基础生命/受伤/死亡

### AI 军团

- 2 个友方军团
- 1～2 个敌方军团
- 总可见单位目标：**100～200**，稳定后再测试 300
- 军团能够自行移动、接敌、攻击和撤退

### 军令

只实现：

- 攻
- 守
- 援
- 撤

玩家能清楚看到军团是否收到命令、正在执行什么、为什么无法执行。

### 军资

只实现一个简化资源：**军资/补给**。

用途限制为 2～3 个：

- 补充部队
- 恢复士气/补给
- 临时强化某支军团

暂不实现完整粮食、木材、铁矿、马匹等经济链。

### 任务

做一封“诏令/军令”驱动的完整任务：

1. 接令
2. 战前选择
3. 进入战场
4. 战斗中出现一次二选一事件
5. 完成或部分失败
6. 结算人物/军队结果

至少一个失败结果允许剧情继续，而不是立即 Game Over。

## 4. PC 与手机验证

### Windows

验证：

- 键鼠操作
- 镜头
- 技能
- 军令选择

### Android

必须在 MVP 阶段真机验证：

- 虚拟摇杆和技能键是否拥挤
- 单手/双手操作负担
- 小屏幕上军令目标是否容易选择
- 100～200 单位下的帧率和发热

不能等 PC 玩法全部做完才考虑手机交互。

## 5. MVP 暂不做

- 汴京完整城市
- 正式历史人物模型
- 方腊/辽/金完整战役
- 官职全树
- 复杂装备系统
- 大型剧情树
- 恋爱系统
- 完整经济生产链
- 城建
- 科技树
- 外交
- 多人
- DLC
- 商城
- DOTS/ECS

## 6. 开发阶段

### M0：工程基线

- 创建 Unity 6.3 LTS 项目
- URP
- Input System
- Windows/Android Build Profile
- Git 基线和 Unity `.gitignore`
- 最小测试场景

验收：Windows 和 Android 都能启动同一空场景。

### M1：英雄手感

- 移动
- 镜头
- 攻击
- 防御/闪避
- 3 个技能
- 木桩敌人

验收：PC 和 Android 上英雄操作都可连续游玩，不依赖 RTS 功能。

### M2：军团 AI

- 单位寻路
- 军团目标
- 自动接敌
- 基础远近战
- 100～200 单位压力测试

验收：两军在无玩家干预时能够从部署走到完整交战并结束。

### M3：军令

- 攻 / 守 / 援 / 撤
- PC 与手机选择方式
- 军令状态反馈

验收：玩家不直接控制士兵，也能可靠改变两支友军的行动方向。

### M4：玩法闭环

- 简化军资
- 一封诏令任务
- 战中选择
- 战役结算
- 本地存档

验收：从接任务到结算可完整玩一轮。

### M5：原型评审

评审问题只有五个：

1. 英雄本身好玩吗？
2. AI 军团看起来像“军队”而不是一群乱跑单位吗？
3. 四种军令够不够表达玩家意图？
4. 手机操作是否比传统 RTS 明显轻松？
5. 玩家是否感到自己的行为确实影响了战局？

任一核心问题明显失败，先调整玩法，不进入正式历史内容制作。

## 7. MVP 通过后的下一步

只有 MVP 通过后，才进入第一段历史 Vertical Slice：

- 选定一个真实北宋末期事件
- 制作一个小型历史场景
- 引入正式美术考据
- 加入 1～2 个历史/原创人物
- 验证“玩法 + 剧情 + 历史”是否能融合

Vertical Slice 通过后，再决定是否正式扩大到《史纪：汴京》的完整制作。
